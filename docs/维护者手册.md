# PACKAGING — 给维护者

本文件是**维护/打包手册**，不是用户文档。用户看 `README.md`。
本插件零构建、零第三方依赖，源码目录本身就是一个可安装包。

---

## 1. 目录结构

```text
dsh-skill-forge/
├── package.json        # 包清单：exports、dsh.bundle.patch、dsh.client.inject、files
├── cordis.patch.yml    # bundle patch：一行 skill-forge 挂 Host + 浏览器两面
├── index.js            # Host 半（ESM，导出 name/version/inject/apply）
├── client.js           # 浏览器半（window.__ModuleLoader__.load 惰性工厂）
├── locale/
│   ├── zh.json         # 插件元信息 title/description（中文）
│   └── en.json         # 同上（英文）
├── icon.svg            # 插件图标（32×32 SVG）
├── README.md           # 用户文档（中文为主）
├── install.ps1         # 人类用：把插件装进 profile（诚实版）
├── uninstall.ps1       # 人类用：从 profile 移除插件（不删技能）
├── PACKAGING.md        # 本文件
└── CONTRACT.md         # 接口契约（唯一真相源；**不随包分发**）
```

| 文件 | 职责 |
|---|---|
| `index.js` | 注册 4 个 `skill_forge_*` 工具 + `/api/dsh-skill-forge/*` 路由；所有资源在 `apply` 内用 `ctx.effect`/`ctx.on` 注册并返回清理 |
| `client.js` | `sidebar.panellist` 行 + `main` 面板（技能库 / 锻造两页签），样式前缀 `sfx_`，只用主题 token |
| `cordis.patch.yml` | patch 层：`insert` 一行 `id: skill-forge` / `name: dsh-skill-forge` + 两个 config 默认值 |
| `package.json` | `exports "."`/`"./client"`；`dsh.bundle.patch` 指向 patch；`dsh.client.inject` 声明客户端依赖 |
| `locale/*.json` | 只有 `meta.title` / `meta.description` 两个 key（面板正文文案在 `client.js` 内联） |
| `install.ps1` / `uninstall.ps1` | 只调用 `dsh plugin ... add/remove`，从不手写 profile 文件 |

> 注意：`locale` 目前只有 `meta.*` 两键，缺失的键由 `client.js` 回退到中文（见 `CONTRACT.md` §2）。

## 2. 双面插件原理

一个 npm 包，两种运行时：

- **Host 面**：`package.json` 的 `exports["."] = "./index.js"`，由 Cordis Loader 在 Host 进程 import，
  导出 `name`/`version`/`inject`/`apply`。`inject = ['tools', 'webServer']` 是硬依赖；
  `llm`、`agentDefaultModel`、`sessionQuery`、`sessions` 一律走 `ctx.get('...', false)` 软取。
- **浏览器面**：`exports["./client"] = "./client.js"`，由 `package.json` 的 `dsh.client`
  清单（`platform: "web"` + `inject: [locale, ui-renderer, ui-layout]`）驱动注入，
  `client.js` 通过 `window.__ModuleLoader__.load({ id, factory })` 注册，导出 `apply`/`inject`。
- **粘合点** `cordis.patch.yml`：**同一行** `skill-forge` 同时被当 Host 插件挂载、又被
  `dsh.client` 字段识别为浏览器插件。所以不要拆成两行，也不要为客户端单独写 patch。
- 客户端调用 Host 用**同源相对路径、不带前导斜杠**：`api/dsh-skill-forge/...`
  （GUI 的 `<base href="./">` 决定解析基准）。写成 `/api/...` 会在子路径部署下失效。

## 3. 打包

在**插件目录内**执行（PowerShell 7）：

```powershell
cd "G:\deepseek通用\_plugins_src\dsh-skill-forge"

$version = (Get-Content -Raw -LiteralPath 'package.json' | ConvertFrom-Json).version
$stage   = Join-Path $env:TEMP "dsh-skill-forge-$version"
$zip     = Join-Path (Get-Location) "dsh-skill-forge-$version.zip"

if (Test-Path -LiteralPath $stage) { Remove-Item -LiteralPath $stage -Recurse -Force }
New-Item -ItemType Directory -Path $stage | Out-Null

# 排除项：CONTRACT.md（内部契约）、node_modules、.git、任何既存 *.zip
Get-ChildItem -LiteralPath . -Force | Where-Object {
    $_.Name -ne 'CONTRACT.md' -and
    $_.Name -ne 'node_modules' -and
    $_.Name -ne '.git' -and
    $_.Name -notlike '*.zip'
} | ForEach-Object { Copy-Item -LiteralPath $_.FullName -Destination $stage -Recurse -Force }

if (Test-Path -LiteralPath $zip) { Remove-Item -LiteralPath $zip -Force }
Compress-Archive -Path (Join-Path $stage '*') -DestinationPath $zip -CompressionLevel Optimal
Remove-Item -LiteralPath $stage -Recurse -Force

Get-Item -LiteralPath $zip | Select-Object Name, Length
```

打完检查 zip 内容（应为扁平一层，无 CONTRACT.md）：

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip = Get-ChildItem -LiteralPath . -Filter 'dsh-skill-forge-*.zip' | Select-Object -First 1
[IO.Compression.ZipFile]::OpenRead($zip.FullName).Entries |
    Select-Object -ExpandProperty FullName | Sort-Object
```

规则：

- **必须排除** `CONTRACT.md`（内部契约，不对外）、`node_modules`（本插件不该有）、`.git`、
  以及任何既存 `*.zip`（否则会把自己打进包）。
- zip 名固定 `dsh-skill-forge-<version>.zip`，`<version>` 取 `package.json` 的 `version`。
- **保留**：`package.json`、`cordis.patch.yml`、`index.js`、`client.js`、`locale/`、`icon.svg`、
  `README.md`、`install.ps1`、`uninstall.ps1`、`PACKAGING.md`。
- 解压后**顶层就是插件目录内容**（不要多套一层目录），`install.ps1` 默认 `-Source $PSScriptRoot`，
  所以用户解压后直接跑脚本即可。

## 4. 版本号约定

- 只改 `package.json` 的 `version`（当前 `1.0.0`）。
- `cordis.patch.yml` **没有版本字段**，不需要跟着改。
- `package.json` 的 `files` 白名单里目前不含 `install.ps1` / `uninstall.ps1` / `PACKAGING.md`；
  它们只用于 zip 交付（npm 包不需要它们）。若将来改成 npm 发布，把这三个加进 `files` 再发。
- 发版顺序：改 `version` → 跑验证清单 → 打 zip → 写发布说明。

## 5. 验证清单

在打包**之前**逐条跑（PowerShell 7）：

```powershell
cd "G:\deepseek通用\_plugins_src\dsh-skill-forge"

# 1) 两个 JS 语法检查（ESM，用 --check 只解析不执行）
node --check index.js
node --check client.js

# 2) 三个 JSON 可解析
node -e "for (const f of ['package.json','locale/zh.json','locale/en.json']) { JSON.parse(require('fs').readFileSync(f,'utf8')); console.log('OK', f) }"

# 3) icon 是合法 SVG（能被 XML 解析，且根元素是 svg）
node -e "const s=require('fs').readFileSync('icon.svg','utf8'); if(!/^\s*<svg[\s>]/.test(s)||!/<\/svg>\s*$/.test(s)) throw new Error('icon.svg 不是完整 SVG'); console.log('OK icon.svg', s.length, 'bytes')"

# 4) locale 两个 key 齐全（zh/en 都是 meta.title + meta.description）
node -e "for (const f of ['locale/zh.json','locale/en.json']) { const j=JSON.parse(require('fs').readFileSync(f,'utf8')); for (const k of ['title','description']) if (!j.meta?.[k]) throw new Error(f+' 缺 meta.'+k); } console.log('OK locale keys')"

# 5) 两个 ps1 的语法（PowerShell 解析器，不执行）
pwsh -NoProfile -Command "[void][scriptblock]::Create((Get-Content -Raw -LiteralPath 'install.ps1'))"
pwsh -NoProfile -Command "[void][scriptblock]::Create((Get-Content -Raw -LiteralPath 'uninstall.ps1'))"

# 6) 安装计划（不执行）
pwsh -NoProfile -File .\install.ps1 -DryRun
pwsh -NoProfile -File .\uninstall.ps1 -DryRun
```

安装验证（**由 Lead / 人类执行，不用脚本代劳**）：

- 用 `plugin_manager`（或 DSH 插件面板）安装本目录，返回 `application: applied` 即视为安装动作被接受。
- 完全重启 DSH Desktop，确认：侧边栏出现「技能锻造炉」；`skill_forge_list` 能返回 `{ skills, root }`；
  `~/.dsh/skills` 未被本次安装创建或修改。
- `application: applied` **只说明安装动作成功**，不等于界面已可见、也不等于艺术/体验验收通过。

## 6. 交付边界（诚实声明）

- `install.ps1` / `uninstall.ps1` 是给**人类以后重装/回滚**用的，不是给 CI 或自动化用的；
  它们不验证 UI，也不判断插件是否真的在界面上出现。
- 脚本找不到可用 CLI 时以退出码 2 结束（install）/ 2（uninstall），**不会**退化成手写 profile 文件。
- `desktop` profile 只能由桌面端自带的 runtime CLI 管理；普通 npm 版 `dsh` 会被 DSH 自身拒绝。
- 本插件的安装动作本身**不产生** GUI 截图与端到端验证证据；这些需要在真机重启后另行确认。
